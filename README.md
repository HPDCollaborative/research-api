# Research API Documentation

Source code for the [HPD Research API Documentation](https://research-api-docs.hpdcollaborative.org) site.

## Architecture Overview

This project has two repositories:

| Repository | Purpose |
|------------|---------|
| [research-api](https://github.com/HPDCollaborative/research-api) | VitePress source code, theme, and build scripts (this repo) |
| [research-api-documents](https://github.com/HPDCollaborative/research-api-documents) | Documentation content (markdown files) |

**How it works:**
1. Documentation content lives in `research-api-documents` with each version as a separate branch (e.g., `2.2`, `2.3`)
2. During build, the `pull:docs` script clones each version branch into the `src/` folder
3. VitePress builds the static site from the merged content
4. Search index is generated by crawling the built HTML pages

## Prerequisites

### Install Bun

This project uses [Bun](https://bun.sh) as the JavaScript runtime (not Node.js/npm).

**Windows:**
```powershell
powershell -c "irm bun.sh/install.ps1 | iex"
```

**macOS:**
```bash
brew install oven-sh/bun/bun
```

**Linux:**
```bash
curl -fsSL https://bun.sh/install | bash
```

**Verify installation:**
```bash
bun --version  # Should be 1.3.5 or higher
```

### Local Search Setup (Optional)

For local development, you can use either:
- **Local search (Fuse.js)** - No setup required, works offline
- **Meilisearch** - Requires a running Meilisearch instance

If using Meilisearch locally (e.g., with ServBay), you'll need the server running before building.

## Local Development Setup

### 1. Clone the Repository

```bash
git clone git@github.com:HPDCollaborative/research-api.git
cd research-api
```

### 2. Install Dependencies

```bash
bun install
```

### 3. Configure Environment

Copy the example environment file:
```bash
cp env.example .env
```

Edit `.env` with your settings:

```env
# Search provider: "local" for Fuse.js, "meilisearch" for Meilisearch
SEARCH_TYPE=local

# Meilisearch settings (only needed if SEARCH_TYPE=meilisearch)
SEARCH_HOST=https://your-meilisearch-host/
SEARCH_KEY=your-public-api-key
ADMIN_KEY=your-admin-api-key
INDEX_NAME=research-api-docs

# Documentation repository
REPO_URL="https://github.com/HPDCollaborative/research-api-documents.git"

# Versions to include (branch names from research-api-documents)
DOC_VERSIONS=["2.2", "2.3"]
```

### 4. Run Setup

This pulls the documentation content and generates the sidebar:
```bash
bun run setup
```

### 5. Start Development Server

```bash
bun run dev
```

The site will be available at `http://localhost:5173`

### 6. Build for Production (Local Testing Only)

```bash
bun run build
```

This will:
1. Build the VitePress static site to `dist/`
2. Generate the search index by crawling the built HTML
3. Push to Meilisearch (if configured)

> ⚠️ **WARNING: DO NOT PUBLISH LOCAL BUILDS**
>
> The `dist/` directory is for **local testing only**. Production documentation is built automatically on the live server through our deployment automation.
>
> **NEVER:**
> - Commit the `dist/` directory to git
> - Manually upload or publish the `dist/` folder
> - Attempt to deploy from your local machine
>
> If you need to publish changes, push your documentation updates to the appropriate branch in `research-api-documents` and notify the Builder team.

Preview the production build:
```bash
bun run preview
```

## Publishing a New Version (e.g., 3.0)

When a new API version is released, follow these steps:

### Step 1: Create the Documentation Branch

In the **research-api-documents** repository:

```bash
# Clone the documents repository
git clone git@github.com:HPDCollaborative/research-api-documents.git
cd research-api-documents

# Create new branch from the latest version
git checkout 2.3  # or whatever the current latest is
git checkout -b 3.0

# Make your changes to the markdown files
# Update frontmatter in index.md to reflect new version

git add .
git commit -m "Add version 3.0 documentation"
git push origin 3.0
```

### Step 2: Notify the Builder Team

The list of versions to build is stored in the `DOC_VERSIONS` variable in the `.env` file **on the live server**. This file is never committed to git and can only be modified by someone with server access.

Until the Builder team adds your new version to `DOC_VERSIONS`, the deployment automation will not pull or build your new branch—even though it exists in the repository.

Once your documentation branch is ready:

1. Contact the HPD Builder team
2. Let them know the new version branch is ready (e.g., "Version 3.0 branch is ready in research-api-documents")
3. The Builder team will SSH into the server and update the `.env` file to include the new version in `DOC_VERSIONS`
4. The Builder team will trigger a deployment to publish the new version

## Updating Existing Documentation

> 🚨 **CRITICAL: NEVER MERGE BETWEEN VERSION BRANCHES**
>
> Each numbered branch (2.2, 2.3, 3.0, etc.) represents a specific version of the API documentation. These branches must remain independent.
>
> **NEVER:**
> - Merge one version branch into another (e.g., never merge 2.3 into 3.0)
> - Rebase version branches against each other
> - Cherry-pick commits between version branches
>
> Merging changes between versions will cause conflicts and **break the documentation**.
>
> Once a new version branch is approved and published, the Builder team will handle merging it into `main`. Do not attempt this yourself.

To update content for an existing version:

1. Clone the documents repository:
```bash
git clone git@github.com:HPDCollaborative/research-api-documents.git
cd research-api-documents
```

2. Switch to the version branch:
```bash
git checkout 2.3  # or whichever version
```

3. Make your edits to the markdown files

4. Commit and push:
```bash
git add .
git commit -m "Update documentation"
git push origin 2.3
```

5. Pushing to a published version branch will automatically trigger a deployment

## Documentation Structure

Each version in `research-api-documents` should have this structure:

```
├── index.md              # Version homepage
├── nav.json              # Navigation/sidebar configuration
├── readme.md             # Version readme
├── content/
│   ├── index.md
│   ├── locations.md
│   ├── materials/
│   ├── nested-materials/
│   ├── polymers/
│   └── substances/
└── data/
    ├── index.md
    ├── accessories.md
    ├── certifications.md
    ├── company.md
    ├── general.md
    ├── notes.md
    ├── parts.md
    ├── product/
    ├── reference.md
    └── voc.md
```

### Frontmatter Requirements

Each `.md` file needs frontmatter for proper indexing:

```yaml
---
title: Page Title
category: Section Name
---
```

The `index.md` in each version root should include the version:

```yaml
---
title: Introduction
category: Introduction
version: "2.3"
---
```

## Troubleshooting

### "Failed to clone" during setup
- Ensure you have SSH access to the GitHub repositories
- Check that the branch names in `DOC_VERSIONS` exist in `research-api-documents`

### Search not working locally
- Set `SEARCH_TYPE=local` for development without Meilisearch
- If using Meilisearch, ensure it's running and accessible

### SSL Certificate Errors (Local Meilisearch)
If using self-signed certificates locally, the build script includes `NODE_TLS_REJECT_UNAUTHORIZED=0` to bypass this.

### Bun version issues
Upgrade bun:
```bash
# If installed via Homebrew
brew upgrade bun

# If installed via curl
bun upgrade
```
